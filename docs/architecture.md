# 아키텍처

## 전체 구조

```
[React 채팅 UI] ──HTTP──▶ [FastAPI]  src/backend/main.py
                               │
                               ▼
        ┌──────────────── Supervisor (LangGraph) ────────────────┐
        │ 1. 요청 해석: 입력 추출 + 이전 상태와 비교 → 의도 판정   │
        │ 2. 입력 확인: 월령·출발지·날짜 (빠지면 되묻기)            │
        │ 3. 다시 실행할 범위 결정 → 서브그래프에 일임              │
        │ 4. 결과 취합 → 나쁜 날 반영·순위 → 응답                   │
        └────────────────────────────────────────────────────────┘
               │ ①                         │ ② 후보별 병렬 (Send)
               ▼                           ▼
     [장소 탐색 서브그래프]     [환경 서브그래프]      [후기·적합도 서브그래프]
     출발지 좌표 확인            날씨 조회               네이버 후기 수집
     월령별 반경 계산            미세먼지 조회           월령 적합도 판정·후기 요약
     TourAPI + 카카오 수집       나쁜 날 판정            실내/야외 판정
     같은 장소 병합 · 편의시설
               │                           │
               └──────────▶ [도메인 도구 · tools.py] ◀──────┘
                            외부 API 호출 · 5초 타임아웃 · 부분 실패 처리
```

- **Supervisor만 대화를 안다.** 서브그래프는 입력을 받아 정해진 구조의 데이터를 돌려주는 순수 처리 단위다.
- **서브그래프는 정해진 순서로 실행되는 LangGraph 서브그래프다.** LLM이 흐름을 결정하지 않는다. 후기·적합도 서브그래프는 판정·요약 단계에서만 LLM을 도구로 부르며, 출력은 고정 JSON으로 검증한다.
- **외부 글(블로그·카페)은 후기·적합도 서브그래프 안에서만 다룬다.** Supervisor에는 검증된 판정 결과만 넘어간다.

## 서브그래프 흐름

각 서브그래프는 `build_graph(prov)`로 Providers를 묶어 컴파일하고, `run(graph, ...)`으로 실행한다. Providers는 그래프 상태에 넣지 않는다.

```
장소 탐색   START → radius → collect ─┬→ facilities (후보별 Send, 병렬) → attach → END
                                       └→ attach (후보 없음)
환경        START ─┬→ weather ─┬→ judge → END
                    └→ dust ────┘
후기·적합도 START → fetch_reviews → judge ─┬→ classify_llm → END   (카테고리로 실내/야외 판단 불가)
                                            └→ END                   (카테고리 규칙으로 결정)
```

- 실패한 외부 API는 각 서브그래프의 `failed_sources`(누적 리듀서)에 모인다.
- 편의시설 최종 판정(공공데이터 → 후기 언급 → 정보 없음)은 장소 탐색과 후기 결과가 모두 필요해서 Supervisor가 합칠 때 `place.resolve_facilities`로 한다.

## Supervisor 의도 판정과 재실행 범위

의도는 규칙으로 판정한다. 이번 메시지에서 추출한 입력을 직전 상태와 비교하고, 장소를 가리키는 표현이 있는지 확인한다.

| 의도 | 예시 | 장소 탐색 | 환경 | 후기·적합도 | 순위 |
|---|---|:-:|:-:|:-:|:-:|
| 새 추천 (입력 완성) | "18개월, 강남역, 토요일" | O | O | O | O |
| 날짜 변경 | "일요일로 바꿔줘" | – | O | – | O |
| 출발지 변경 | "판교에서 출발할게" | O | O | O | O |
| 월령·낮잠 변경 | "아 24개월이에요" | O (반경 변경) | O | O (적합도 변경) | O |
| 장소 상세 | "2번째 곳 더 알려줘" | – | – | – | – (저장된 카드로 응답) |
| 새로 시작 | "처음부터 다시" | 상태 초기화 후 되묻기 | | | |
| 범위 밖 | "아기 이유식 추천해줘" | 서비스 범위 안내 | | | |

- 이전 실행 결과(후보, 장소별 환경·후기 결과, 카드)는 세션 상태에 저장하고, 재실행하지 않는 단계는 저장된 결과를 재사용한다.
- 변경된 입력이 잘못되면(지난 날짜, 월령 범위 밖 등) 서브그래프를 실행하지 않고 되묻는다. 이전 추천 결과는 유지한다.

## 파일 배치

```
src/backend/
├── main.py              # FastAPI 엔드포인트
├── agent.py             # Supervisor 그래프 (의도 판정 · 입력 확인 · 일임 · 취합)
├── agents/
│   ├── place.py         # 장소 탐색 서브그래프
│   ├── environment.py   # 환경 서브그래프
│   └── review.py        # 후기·적합도 서브그래프
├── tools.py             # 외부 API 호출 (Providers 주입, 타임아웃, 부분 실패)
├── constants.py         # 공통 표시 문구·키
├── cards.py             # 결과 카드 생성 · LLM 출력 검증
└── retriever.py         # (RAG 도입 시)
```

## 공통 원칙
- 외부 API 하나가 실패하거나 5초 안에 응답하지 않으면 해당 항목만 "정보를 불러오지 못함"으로 표시한다.
- API 키는 저장소 루트 `.env`에만 두고 백엔드에서만 사용한다.
- API 요청·응답 형식은 [api-spec.md](api-spec.md)를 참고한다.
